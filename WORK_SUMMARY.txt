## Архитектура OTA

### Компоненты
- **Updater.kt**: проверка обновлений, загрузка APK, SHA-256 верификация, установка
- **UpdateDialog.kt**: диалоги обновлений, ошибок, «Что нового», разрешений, паузы
- **VersionHistory**: отслеживание запусков для показа «Что нового»
- **MainActivity.kt**: интеграция OTA в UI, автопроверка при запуске

### Источник обновлений
- **Манифест:** `https://github.com/neveruserlos/nelev/releases/latest/download/version.json`
- **Структура:**
  ```json
  {
    "versionCode": 39,
    "versionName": "1.9.4",
    "apkUrl": "https://github.com/.../nelev-app-release-1.9.4.apk",
    "apkSha256": "6eb390cd5d69722d8bbba7dafde6b63d8bbad99066939c6bfaecb5e79d07df19",
    "changelog": "..."
  }
  ```

### Логика проверки обновлений
- **Автопроверка:** при запуске приложения (не чаще раза в 3 часа)
- **Тихая:** если обновления не приостановлены, показывается уведомление
- **Ручная:** кнопка «Проверить обновление» в Settings
- **Пауза:** пользователь может приостановить на выбранный срок

### Безопасность
- SHA-256 верификация загруженного APK
- FileProvider для безопасного доступа к APK
- Разрешение `REQUEST_INSTALL_PACKAGES` (Android 8+)
- Диалог предупреждения перед запросом разрешения

## Техническая информация

### Версионирование
- **Единственный источник:** `X:\nelev\app\version.properties`
- **Формат:**
  ```properties
  versionCode=39
  versionName=1.9.4
  ```
- **Автоматизация:** `tools/bump-version.ps1`

### Сборка и релиз
```powershell
# Сборка
cd X:\nelev\app
.\gradlew.bat assembleRelease -x lintVitalAnalyzeRelease -x lintVitalReportRelease -x lintVitalRelease

# Bump версии
.\tools\bump-version.ps1 -VersionName "1.9.5"

# Релиз (создаёт GitHub Release + загружает APK и version.json)
.\tools\release.ps1 -NotesFile notes.txt
# или если APK уже собран:
.\tools\release.ps1 -SkipBuild -NotesFile notes.txt
```

### Подпись APK
- **Keystore:** Android debug keystore
- **CN:** Android Debug
- **SHA-256:** `26c900cf9ee85cf26506ebbd2f369158a130d37d9d66fe8bee2766d4ca715e98`
- **Примечание:** обновления устанавливаются поверх предыдущих версий

### Кодовая база

## Известные ограничения

1. **On-device тестирование:** нет доступа к физическому устройству или эмулятору через adb
2. **CDN задержка:** GitHub Releases CDN может задерживать обновление `/latest/download` на несколько минут
3. **Debug keystore:** использование отладочного хранилища ключей (для production нужен release keystore)
